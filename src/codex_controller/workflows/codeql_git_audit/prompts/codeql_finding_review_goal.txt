/goal 独立审查代码位置 `${source_path}:${source_line}`（任务标识 `${finding_id}`），判断该位置及相关执行路径是否确实存在所描述类型的问题。

本次只核验下面这个具体问题类型：

- 问题类型：`${problem_name}`
- 类型说明：`${problem_description}`
- 当前代码位置的待核验描述：`${candidate_description}`
- 源码位置：`${source_path}:${source_line}`

以上描述仅用于界定核验对象，不代表问题已经成立，也不能作为问题存在的证据。

## 审查要求

1. 从源码位置出发阅读实际代码、相关调用者与被调用者，独立还原预期行为、数据流、控制流和运行约束。只核验上述具体类型，不扩展为通用问题类型枚举，也不预设结论。
2. 同等力度地寻找支持与否定该问题的代码证据，包括输入来源、上游校验、类型和范围约束、错误处理、对象生命周期、线程约束、编译条件、生产配置、不可达分支以及测试或示例专用路径。
3. 如判断问题存在，必须验证从外部输入或不可信状态到触发点及实际影响的完整可达路径，明确具体问题类型、触发条件和能够确定的 CWE 编号。
4. 如判断问题不存在，必须指出阻止该问题发生的具体代码或运行约束，不能只以“未发现”作为理由。
5. 证据不足或结论依赖仓库外行为时使用 `inconclusive`，不要猜测缺失事实。
6. 不修改源码、配置、测试或其他文件。

## 输出约束

只允许创建或修改 `${review_path}`。该文件必须是 UTF-8 合法 JSON，不能包含 Markdown fence、注释或尾随逗号，格式如下：

```json
{
  "finding_id": "${finding_id}",
  "verdict": "problem",
  "problem_type": "经代码核验的具体问题类型；不成立时填写本次被排除的类型",
  "cwe_ids": ["CWE-787"],
  "confidence": "high",
  "summary": "客观结论及核心代码依据",
  "attack_path": [
    "外部输入或不可信状态",
    "代码中的传播步骤",
    "触发点与实际影响"
  ],
  "evidence": [
    {
      "path": "仓库相对文件路径",
      "line": 123,
      "symbol": "代码符号",
      "explanation": "该处支持结论的原因"
    }
  ],
  "counter_evidence": ["已核验的相反证据或约束"],
  "impact": "存在问题时说明实际影响；不存在时说明为何不会产生影响",
  "trigger_conditions": ["所需输入、状态、权限或配置"],
  "remediation": "存在问题时给出最小修复建议；否则为空字符串"
}
```

`verdict` 只能是 `problem`、`no_problem`、`inconclusive`；`problem_type` 必须准确描述本次核验的具体类型，不能填写宽泛的“安全问题”或罗列无关类型。`cwe_ids` 必须是数组，仅填写能够从代码确认的 CWE 编号，无法确定或问题不存在时留空。`confidence` 只能是 `high`、`medium`、`low`。`evidence` 必须是数组；`problem` 至少需要一项精确到路径、行号和符号的代码证据，并给出非空的可达路径与实际影响。

只有完成代码路径核验并写入 `${review_path}` 后任务才算完成。
